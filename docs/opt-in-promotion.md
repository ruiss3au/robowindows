# Opt-in modes and optional diagnostics — 2026-09-10

The user approved wider availability, not a new quality certification. DynRec
fixed-20k and GPU are ordinary opt-in choices in both build variants. Existing
profiles and Normal/Software defaults are unchanged. CPU correctness remains a
manual, current-core-build prerequisite for DynRec. Known Windows audio issues
and unfinished clock/thermal/long-run gates remain documented and parked.

## Implementation and safety

- Removed role/build eligibility restrictions for fixed-20k and GPU across the
  settings/store/controller/child boundary. Higher/automatic cycle policies still
  require a debug experimental copy. Balanced timing now follows DynRec execution
  regardless of role; ordinary Normal keeps its legacy timing.
- Retained private non-aliased media ownership, fresh generation checks, clean
  shutdown prerequisite, durable journal, isolated process and Normal recovery.
  Ordinary-role journal handoff, clean completion and quarantine/recovery now use
  the same path. Recovery and GPU failures still use Software without erasing GPU.
- Added app-wide Show performance counters (initially off), shared between Tests
  and session controls. Existing live DynRec residency labels are hidden without
  disabling progress watchdogs, aggregate logs or fallback/error notifications.
- CPU tests have separate build-specific status and Run CPU tests / Run again.
  A rerun invalidates prior success before starting disposable fixtures; cancelled,
  incomplete and failed runs cannot authorize DynRec. Recovery blocks testing.
