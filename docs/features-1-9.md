# Feature audit: items 1–9

Status reflects evidence from the current source tree and the SM-T500 on
2026-08-09. “Implemented” is not used as a substitute for a missing device
observation.

| Item | Current implementation | Evidence | Remaining gate |
|---|---|---|---|
| 1. Physical input bridge | External non-virtual keyboards and mice receive session handles; typed key/mouse/touch/cancel records preserve required fields; capture, focus loss, pause, and disconnect cancel held state; history is bounded. | Host/JNI tests pass. An unlocked physical run recorded 60 Inateck key transitions and 454 LIFT events with zero drops; focus loss produced cancellation. A guest capture/release run recorded 175 LIFT events, one cancellation, zero drops, and ended `UNCAPTURED`. | The SDD’s release-level ten-run/reconnect matrix remains broader than this feature checkpoint. |
| 2. DOSBox Pure lifecycle | Pinned core is hosted directly with explicit starting/running/failed/stopped state, pause/resume, clean unload, and no RetroArch frontend. | SM-T500 direct-boot test confirms start, pause, resume, media callback, and clean stop. | None for the tested disposable IMG path. |
| 3. Guest display | RoboWindows owns a black `SurfaceView`; XRGB8888 frames are scaled with aspect-preserving letterboxing. Upstream messages/OSD are not rendered. | Strict SM-T500 run rendered a nonblank 640×400 frame to a 1946×1074 surface as 1718×1074 content with 114-pixel side bars; product-source prohibition test passes. | None for the tested disposable IMG path. |
| 4. Machine creation | DOS and Windows-family profiles are created from IMG/IMA/VHD. DOS defaults to 16 MB/normal; Windows defaults to the SM-T500-validated 64 MB/normal compatibility core. The automatic Windows core remains an explicitly experimental preset. ISO is correctly treated as attachable, not directly bootable. | Isolated SM-T500 creation probe verifies DOS and Windows defaults plus generated direct-boot config. | Normal document-picker interaction remains a manual UI check. |
| 5. Storage/media import | Imports stream into `.part`, fsync, atomically finalize, SHA-256 hash, protect the source, clone writable disks, preflight known sizes, and roll back failures. Later ISO/disk media has durable provenance. | Isolated SM-T500 probe verifies real `ContentResolver` import, immutable source, writable clone isolation, attached ISO record, hash, and cleanup. | Provider-specific insufficient-space/error matrix is not yet exhaustive. |
| 6. Machine library | Machines-first home lists family and last-used state with Settings and Start actions; recovery warning appears independently. | Current SM-T500 machines, empty-library, recovery, diagnostics, and Add machine screens were visually inspected after unlock. | Populated-card tap paths remain covered by implementation/backend tests rather than a disposable visible profile. |
| 7. Configuration | DOS compatibility, Windows compatible/experimental, and sound controls atomically rewrite config and synchronously persist schema v5. | Host config tests and isolated SM-T500 update/reload probe pass; the real `incoming` profile was persistently changed to the compatible core through this UI. | Tap-path visual check after unlock. |
| 8. Session controls | Exit, pause/resume, restart, change media, and capture/release mouse are RoboWindows controls; native async load failure returns to the library. Restart queues `retro_reset` on the core thread rather than unsafely reinitializing the shared core. | SM-T500 automation confirms pause/resume, media replacement, guest restart back to BOOT, audio startup, and orderly exit. Physical capture/release was also confirmed. | None for the tested disposable IMG path. |
| 9. Persistence/recovery | Versioned profiles migrate v1–v5, configs replace atomically, `.part` files recover, attached media persists, and active-session markers distinguish interrupted from orderly stop. | SM-T500 probe confirms migration, round-trip, atomic config, interrupted-import cleanup, marker set/clear, and isolated cleanup. A real stale-session banner was displayed and its Dismiss action persistently cleared it. | A deliberate process-kill repetition is optional additional coverage. |

The debug APK and its SHA-256 sidecar are generated under `artifacts/`. Device
tests use disposable files only and restore the tablet’s original power setting.
